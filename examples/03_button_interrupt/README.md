# 03. Кнопка по прерыванию

Нажатие на GPIO9 больше не ищется в цикле. Периферия GPIO сама вызывает функцию `button_isr` на перепаде 1 → 0. Обработчик только кладёт номер вывода в очередь. Задача `button_task` спит на этой очереди, а проснувшись, подтверждает нажатие, переключает светодиод и печатает счётчик.

Так устроена кнопка в исходном проекте с OLED: там тоже есть `isr_handler`, очередь `gpio_evt_queue` и задача `button_task`.

## Зачем очередь, если есть прерывание

Код внутри прерывания выполняется «посреди» любой другой работы, иногда при кратковременно выключенной внешней памяти. Поэтому обработчик обязан быть коротким и имеет право вызывать только функции с суффиксом `FromISR`.

`printf`, `ESP_LOGI` и `vTaskDelay` из прерывания вызывать нельзя: они берут блокировки и могут надолго занять процессор. Очередь переносит событие в обычную задачу, где эти вызовы разрешены.

```text
кнопка → периферия GPIO → button_isr → очередь → button_task → лог и светодиод
```

## Железо

| Сигнал | GPIO | Уровень |
| --- | --- | --- |
| Кнопка (или BOOT) | 9 | 0 = нажато, внутренняя подтяжка вверх |
| Светодиод | 8 | включение уровнем `LED_ON_LEVEL` |

Прерывание настроено на спад (`GPIO_INTR_NEGEDGE`): оно срабатывает в момент нажатия, а не всё время, пока кнопку держат.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/03_button_interrupt
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

## Разбор по шагам

1. `gpio_config()` включает вход, подтяжку и тип прерывания.
2. `xQueueCreate(8, sizeof(uint32_t))` создаёт ящик на 8 номеров выводов.
3. `gpio_install_isr_service(0)` поднимает общий для всех GPIO диспетчер прерываний. Второй раз в той же программе его вызывать не нужно.
4. `gpio_isr_handler_add()` привязывает `button_isr` к GPIO9. Последний аргумент придёт в обработчик как `void *arg`. Мы передаём номер вывода, чтобы один обработчик мог обслуживать несколько кнопок.
5. `xTaskCreate()` запускает задачу разбора. В ESP-IDF размер стека задаётся **в байтах**. В учебниках по «голому» FreeRTOS стек часто указывают в словах — на ESP32 ту цифру надо умножать на 4, иначе задача сорвётся с переполнением стека.
6. В задаче после события стоит пауза 40 мс и повторное чтение уровня. Прерывание ловит и настоящий спад, и дребезг. Подтверждает нажатие только повторное чтение.

Атрибут `IRAM_ATTR` размещает обработчик во внутренней RAM, а не во flash. Для GPIO это рекомендуемый вид обработчика.

## Что вы должны увидеть

```text
I (xxx) button_isr: GPIO9 нажатие 1, светодиод включён
```

Удержание кнопки даёт одно сообщение. Следующее появится после отпускания и нового нажатия.

## Частые ошибки

- Сообщение в логе есть, а светодиод не меняется. Другой номер GPIO или другая полярность, см. пример 01.
- В мониторе мусор и перезагрузка сразу после нажатия. Из обработчика прерывания вызвана обычная, не `FromISR`, функция. В этом примере так делать негде: обработчик состоит из одной отправки в очередь.
- `gpio_install_isr_service` вернула `ESP_ERR_INVALID_STATE`. Сервис уже установлен. В одном приложении его ставят один раз.
