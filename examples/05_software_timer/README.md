# 05. Программные таймеры FreeRTOS

Два таймера без отдельной задачи на каждый:

- **периодический** срабатывает каждую секунду и увеличивает счётчик;
- **одноразовый** срабатывает один раз через пять секунд после старта.

Оба обслуживает одна системная задача `Tmr Svc`. Ваш код — это короткая функция, которую задача вызывает в нужный момент.

Железо не требуется.

## Чем этот таймер не является

Это не аппаратный счётчик внутри чипа. Программный таймер хорош, когда нужно «раз в секунду сделать что-то короткое» и не хочется заводить ради этого ещё одну задачу с `vTaskDelay`.

Он плохо подходит, если:

- интервал меньше одного тика FreeRTOS (в ESP-IDF тик по умолчанию 10 мс);
- действие внутри колбэка долгое: сеть, flash, ожидание очереди;
- нужна точность в микросекундах.

Для таких случаев есть [пример 06](../06_hardware_timers/README.md): `esp_timer` и аппаратный GPTimer.

## Правила колбэка

Пока выполняется колбэк одного программного таймера, остальные программные таймеры ждут. Поэтому колбэк должен быстро вернуться.

Нельзя вызывать отсюда `vTaskDelay` и нельзя ждать мьютекс, который может быть занят задачей, а та задача ждёт таймер. Получится взаимное ожидание, и `Tmr Svc` замолчит.

Короткий `ESP_LOGI`, как в этом примере, — нормальная граница. Всё, что длиннее, лучше перекладывать в отдельную задачу через семафор или очередь.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/05_software_timer
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

## Что вы должны увидеть

```text
I (xxx) sw_timer: периодический таймер, тик 1
I (xxx) sw_timer: периодический таймер, тик 2
...
W (xxx) sw_timer: одноразовый таймер сработал. Повторно сам он не запустится
I (xxx) sw_timer: main видит 3 тиков периодического таймера
```

Предупреждение одноразового таймера появляется один раз, около пятой секунды. Периодические строки продолжаются.

## Как устроен вызов

`xTimerCreate` только описывает таймер и не запускает его. Время начинает идти после `xTimerStart`. Период задаётся в тиках, поэтому миллисекунды переводят через `pdMS_TO_TICKS`.

`pdTRUE` в третьем аргументе делает таймер периодическим: после колбэка период начинается заново. `pdFALSE` — таймер останавливается, пока его явно не запустят снова.

Четвёртый аргумент (`id`) в колбэк сам не приходит, но его можно прочитать функцией `pvTimerGetTimerID(timer)`. Так один колбэк обслуживает несколько таймеров и различает, кто его вызвал. В этом примере у каждого таймера своя функция, а `id` оставлен как метка.
