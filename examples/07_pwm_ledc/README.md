# 07. ШИМ (LEDC): яркость светодиода

Периферия LEDC переключает GPIO8 с частотой 5 кГц. Программа задаёт не «включить навсегда», а долю периода, в течение которой светодиод горит. Доля плавно едет от 0% к 100% и обратно за 1.5 секунды. Промежуточные шаги считает само железо, цикл в `app_main` только запускает следующий переход.

## Слова, которые здесь встречаются

- **ШИМ, PWM** — сигнал с постоянной частотой и меняющейся шириной импульса.
- **Duty** — сколько времени внутри одного периода вывод находится в активном состоянии. В LEDC это целое число, не процент. При 13 битах диапазон 0…8191.
- **Частота** — как часто период повторяется. 5 кГц для глаза уже не мерцает. Для мотора частоту иногда снижают, для светодиодной ленты оставляют несколько килогерц.
- **Fade** — аппаратное изменение duty от текущего значения к новому за заданное время.

На ESP32-C3 у LEDC есть только режим `LEDC_LOW_SPEED_MODE`. Высокоскоростного режима, который есть на старших ESP32, здесь нет. Для светодиода это ничего не меняет.

## Железо

| Сигнал | GPIO | Замечание |
| --- | --- | --- |
| Светодиод | 8 | Полярность задаёт `LED_ON_LEVEL` |

Если светодиод становится ярче, когда код просит «яркость 0», поменяйте `LED_ON_LEVEL` на 1. Функция `duty_for_brightness()` как раз прячет эту разницу: остальной код говорит процентами яркости.

Адресный светодиод WS2812 ШИМом не управляется.

Внешний светодиод подключают через резистор 330 Ом. Не подключайте мотор или лампу 12 В прямо к GPIO: вывод отдаёт единицы миллиампер при 3.3 В. Для мотора нужен транзистор, а этот пример остаётся про форму сигнала.

## Сборка

```bash

idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

## Как устроен код

1. `ledc_timer_config()` задаёт частоту и разрядность общего таймера. Один таймер могут делить несколько каналов, тогда частота у них общая, а duty у каждого свой.
2. `ledc_channel_config()` привязывает канал 0 к GPIO8 и к этому таймеру.
3. `ledc_fade_func_install(0)` нужна один раз, иначе плавное изменение duty недоступно.
4. `ledc_set_fade_with_time()` записывает цель и длительность. `ledc_fade_start(..., LEDC_FADE_NO_WAIT)` запускает переход и сразу возвращает управление. Пауза в цикле чуть длиннее перехода, чтобы новый fade не оборвал предыдущий.

Разовое, не плавное, изменение делается парой `ledc_set_duty()` и `ledc_update_duty()`. Пока нет `update_duty`, новое значение только записано в тень и на вывод не попало.

## Что вы должны увидеть

Светодиод медленно разгорается и гаснет. В мониторе чередуются две строки:

```text
I (xxx) pwm: яркость 0 -> 100
I (xxx) pwm: яркость 100 -> 0
```

## Частые ошибки

- `ledc_set_fade_with_time` возвращает `ESP_ERR_INVALID_STATE`. Забыли `ledc_fade_func_install`.
- Яркость меняется рывками, а не плавно. Слишком короткий `time_ms` или следующий `fade_to` вызывается раньше, чем кончился предыдущий.
- Светодиод едва светится на «100». Перепутана полярность, см. `LED_ON_LEVEL`.
