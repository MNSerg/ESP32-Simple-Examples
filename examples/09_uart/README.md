# 09. UART: эхо байтов

Пример поднимает UART1 на GPIO21 (передача) и GPIO20 (приём), скорость 115200 8N1. Всё, что пришло, печатается в монитор USB и отправляется обратно с приставкой `echo:`.

Монитор `idf.py monitor` и этот UART — разные каналы. Лог `ESP_LOGI` виден в мониторе всегда. Байты UART видны на GPIO21/GPIO20.

## Две проверки

**Петля на одной плате.** Перемычка между GPIO21 и GPIO20. Пример при старте сам пишет приветствие в TX, тут же читает его из RX и отвечает `echo: ...`. Дальше раз в момент приветствия вы увидите одну обменную строку. Новые байты сами не появятся: их некому набирать. Петля доказывает, что TX и RX живы.

**Переходник USB-UART.** Соединения:

| Переходник | ESP32-C3 |
| --- | --- |
| RX | GPIO21 (TX чипа) |
| TX | GPIO20 (RX чипа) |
| GND | GND |

TX соединяют с RX крест-накрест. Две земли обязательны. Уровни только 3.3 В: переходник на 5 В без преобразователя уровней сюда подключать нельзя.

В терминале на компьютере выставьте 115200, 8 бит данных, без чётности, 1 стоп-бит. Наберите строку. В терминале она вернётся, в мониторе ESP появится `принято N байт`.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/09_uart
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

## Как устроен код

1. `uart_driver_install` включает драйвер. Приёмный буфер — 1024 байта в ОЗУ: периферия успеет сложить байты, даже если задача занята. Передающий буфер равен 0, поэтому `uart_write_bytes` завершается, когда байты забрало оборудование.
2. `uart_param_config` записывает скорость и формат кадра.
3. `uart_set_pin` подключает UART1 к выбранным GPIO. На ESP32 почти любой свободный вывод можно отдать UART через матрицу GPIO, фиксированной «только такой ножки» нет. `UART_PIN_NO_CHANGE` оставляет RTS и CTS неподключёнными: аппаратное управление потоком выключено.
4. Цикл читает с таймаутом 200 мс. Ноль байт означает «пока тишина», а не сбой.

UART0 на C3 часто связан с выводами GPIO20/GPIO21 по умолчанию, но пример сознательно берёт UART1 и сам назначает те же удобные выводы. Консоль при этом остаётся на USB (`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`), поэтому прошивка лога и обмен байтами друг другу не мешают.

## Что вы должны увидеть

В мониторе сразу:

```text
I (xxx) uart: UART1  115200 8N1, TX=GPIO21 RX=GPIO20
```

С перемычкой следом придёт что-то вроде:

```text
I (xxx) uart: принято 52 байт: ESP32-C3 UART. Наберите текст...
```

Без перемычки и без переходника этой строки не будет. Программа при этом не зависает: она просто ждёт байты.

## Частые ошибки

- Текст в терминале есть, эха нет. TX и RX подключены прямо, а не крест-накрест, или забыта общая земля.
- В мониторе кракозябры вместо принятой строки. Разная скорость на двух концах.
- После прошивки пропал и монитор. Порт консоли случайно переведён с USB на UART. В `sdkconfig.defaults` этого примера консоль зафиксирована на USB Serial/JTAG.
