# 14. TCP-сервер

Плата поднимает сеть `ESP32C3-DEMO` (пароль `esp32c3demo`) и слушает TCP-порт `3333`. Всё, что клиент прислал, возвращается обратно с приставкой `echo:` и печатается в монитор.

С ноутбука, который подключён к этой сети:

```bash
nc 192.168.4.1 3333
```

Если программы `nc` нет, подойдёт любой TCP-клиент на адрес `192.168.4.1` и порт `3333`. На Windows это может быть `ncat` из Nmap или режим Raw в PuTTY.

Наберите `hello` и нажмите Enter. В терминале появится:

```text
ESP32-C3 TCP. Наберите строку.
echo: hello
```

В мониторе платы — строка `принято: hello`.

Пока обслуживается один клиент, второй `accept` не вызывается. После закрытия первого соединение снова можно открыть.

## Что такое TCP в этой программе

Сокет `listen_fd` сам данные не перевозит. Он только принимает стук в дверь. `accept` создаёт новый сокет `client` на каждое соединение, и уже `recv` / `send` работают с ним.

Порядок на стороне сервера всегда один:

1. `socket` — создать дескриптор;
2. `bind` — занять локальный порт 3333 на всех интерфейсах (`INADDR_ANY`);
3. `listen` — разрешить входящие;
4. `accept` — дождаться клиента;
5. `recv` и `send` — байты;
6. `close` — отпустить клиента.

`htons` и `htonl` переворачивают число в сетевой порядок байтов. Порт в структуре `sockaddr_in` всегда хранят так, даже если на ESP32-C3 и на ноутбуке порядок одинаковый: сокет этого требует.

`recv` возвращает 0, когда клиент закрыл соединение. Отрицательное значение — ошибка, её код лежит в `errno`. Положительное — сколько байт лежит в буфере. Это не строка языка C, пока вы сами не запишете в конец ноль. Пример это делает, чтобы отдать буфер в `%s`.

TCP не знает, где кончается ваше сообщение. Если клиент отправил `hello`, `recv` может вернуть и 5 байт, и эти 5 байт вместе со следующим куском, если тот уже пришёл. Для учебного эха это не мешает. В настоящем протоколе границу кадра задают сами: перевод строки, длина впереди или пауза.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/14_tcp_server
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Телефон и ноутбук должны быть в сети `ESP32C3-DEMO`, не в домашнем Wi-Fi. Иначе адреса `192.168.4.1` с них не видно.

## Что вы должны увидеть

Сразу после старта:

```text
I (xxx) tcp: слушаю 3333. С ноутбука в сети ESP32C3-DEMO:  nc 192.168.4.1 3333
```

После `nc`:

```text
I (xxx) tcp: соединение с 192.168.4.2
I (xxx) tcp: принято: hello
I (xxx) tcp: клиент закрыл соединение
```

## Частые ошибки

- `nc` пишет `Connection refused`. Сервер ещё не дошёл до `listen`, или порт не 3333. Посмотрите, есть ли в мониторе строка «слушаю».
- `nc` молчит и потом `timed out`. Ноутбук подключён к другой сети Wi-Fi.
- В мониторе принятый текст обрывается. Буфер примера — 127 байт за один `recv`. Более длинная пачка придёт несколькими кусками и несколькими ответами `echo:`.
