# 16. BLE-сервер (NimBLE)

Плата объявляет имя `ESP32C3-BLE`. Телефон подключается к ней по Bluetooth Low Energy, читает и записывает характеристики GATT и может подписаться на уведомления со счётчиком.

На ESP32-C3 есть только BLE. Профиль классического Bluetooth, в том числе «последовательный порт» SPP, на этом чипе не существует. Если программа на телефоне ищет именно SPP, она плату не увидит. Нужен BLE-сканер. Удобный бесплатный — nRF Connect (Android и iOS).

## Что нажимать в nRF Connect

1. Прошейте пример и откройте монитор: в логе должна быть строка, что NimBLE запущен.
2. В nRF Connect нажмите Scan и выберите `ESP32C3-BLE`.
3. Connect.
4. Откройте сервис с UUID `00FF`.
5. Характеристика `FF01`. Read покажет один байт `00`. Write значение `01` — светодиод GPIO8 включится, `00` — выключится. В мониторе появится строка про светодиод.
6. Характеристика `FF02`. Нажмите значок подписки (три стрелки, notify). Раз в секунду значение будет расти. Это счётчик `uint32`, младший байт первый.

Пока подписки нет, счётчик внутри платы всё равно растёт, но в эфир не уходит: уведомление без подписки стек не шлёт.

## Словарь на одну страницу

| Слово | Что это в примере |
| --- | --- |
| Объявление, advertising | Плата регулярно передаёт имя, ещё не будучи подключенной |
| GATT | Таблица данных, которую телефон читает после подключения |
| Сервис | Группа характеристик. Здесь один, UUID `00FF` |
| Характеристика | Одно значение. `FF01` — светодиод, `FF02` — счётчик |
| Notify | Плата сама присылает новое значение, без отдельного Read |
| Центр / периферия | Телефон / плата |

16-битные UUID в примере короткие специально, чтобы их было видно в сканере. Для своей разработки вне учебной платы возьмите 128-битный UUID: короткие номера выдаёт Bluetooth SIG, и чужой `00FF` когда-нибудь пересечётся с вашим.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/16_ble_server
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

`sdkconfig.defaults` включает Bluetooth и выбирает стек NimBLE. Bluedroid в этом примере не используется: для одного сервера NimBLE меньше и проще.

## Как устроен код

1. NVS нужен стеку так же, как Wi-Fi: во flash лежит калибровка радио.
2. `nimble_port_init()` поднимает контроллер и хост.
3. Таблица `s_services` описывает сервис и две характеристики. Ноль в конце массива — признак конца, без него стек не поймёт, где остановиться.
4. `ble_gatts_add_svcs()` публикует таблицу. Поле `val_handle` заполняет сам стек: по этому номеру потом отправляют notify.
5. `nimble_port_freertos_init()` создаёт задачу стека. Объявление начинается не здесь, а в `on_sync`, когда радио действительно готово.
6. Запись характеристики обрабатывает `gatt_access`. Телефон присылает байты в буфере `os_mbuf`, не в обычном массиве. `ble_hs_mbuf_to_flat` копирует их в переменную.
7. `notify_task` раз в секунду, если есть соединение и подписка, собирает такой же буфер и отдаёт его `ble_gatts_notify_custom`. После вызова буфер принадлежит стеку, второй раз его освобождать не нужно.

Пока идёт `nimble_port_run`, ваша `app_main` уже свободна. Поэтому мигающий счётчик живёт в отдельной задаче, а не в колбэке стека.

## Что вы должны увидеть

```text
I (xxx) ble: NimBLE запущен. Откройте nRF Connect и найдите ESP32C3-BLE
I (xxx) ble: ищем телефон. Имя в эфире: ESP32C3-BLE
I (xxx) ble: телефон подключился, handle 1
I (xxx) ble: светодиод включён (байт 1)
I (xxx) ble: уведомления счётчика: включены
```

После отключения телефона объявление начинается снова. Имя опять видно в сканере.

## Частые ошибки

- Платы нет в поиске. В мониторе нет строки «ищем телефон»: стек не дошёл до `on_sync`. Или на телефоне выключен Bluetooth, или сканер ищет классические устройства, а не BLE.
- Write не меняет светодиод. В характеристику ушёл не один байт. В nRF Connect тип записи — BYTE или UINT8, значение `01`, не строка `"01"`.
- Notify молчит. Подписка не включена, либо подписались не на `FF02`.
- Рядом запущен пример Wi-Fi, и оба плохо работают. Радио одно. В одном проекте Wi-Fi и BLE можно совмещать, но это отдельная настройка сосуществования; эти примеры её не включают и рассчитаны на запуск по одному.
