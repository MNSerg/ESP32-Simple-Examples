# 19. NVS: данные во flash

Пример помнит, в который раз его включили. Число лежит не в переменной, а в разделе flash `nvs`. Рядом хранится короткая строка `boot N`.

Проверка:

1. Прошейте пример и посмотрите в мониторе номер загрузки.
2. Нажмите RESET на плате. Номер станет на единицу больше.
3. Отключите USB, подождите пару секунд, подключите снова. Номер снова вырастет.

Так ведут себя настройки, которые должны пережить и сон, и выдёргивание кабеля: имя Wi-Fi, калибровка, «экран, который пользователь выбрал в прошлый раз». Счётчик из примера глубокого сна (`RTC_DATA_ATTR`) пункт 3 не переживает.

## Как устроено хранилище

NVS — не файловая система. Нет каталогов и нет произвольной записи «с середины файла». Есть пространство имён и ключи.

В примере пространство называется `storage`, ключи — `boots` (int32) и `note` (строка). Имя пространства и имя ключа не длиннее 15 символов.

Чужой код на той же плате, например драйвер Wi-Fi, использует другие пространства. Открывать чужое пространство и писать туда свои ключи не нужно: `nvs_open` с новым именем создаёт своё.

`nvs_get_*` возвращает `ESP_ERR_NVS_NOT_FOUND`, если ключа ещё не было. Для первого включения это нормальный путь, не авария. `ESP_ERROR_CHECK` на эту ошибку вешать нельзя: программа остановится ровно на чистой плате.

`nvs_set_*` меняет значение в кэше. `nvs_commit` записывает кэш во flash. Закрытие `nvs_close` само по себе flash не гарантирует. Один `commit` на пачку изменений лучше, чем `commit` после каждого ключа: ресурс стирания flash ограничен сотнями тысяч циклов на блок, а не бесконечен.

Большие массивы (журнал на мегабайт, картинки) в NVS не кладут. Для них есть раздел FAT или SPIFFS. NVS хорошо держит настройки и счётчики.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/19_nvs_storage
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Полная перепрошивка через `idf.py flash` обычно **не** стирает раздел NVS, и счётчик продолжается. Счётчик обнулится, если стереть весь чип (`idf.py erase-flash`) или если программа сама вызовет `nvs_flash_erase()`.

## Что вы должны увидеть

Первый запуск на чистом разделе:

```text
I (xxx) nvs: ключ boots ещё не создан, начинаю с нуля
I (xxx) nvs: ключ note ещё не создан
I (xxx) nvs: загрузка 1 записана. Заметка теперь "boot 1"
```

После RESET:

```text
I (xxx) nvs: прошлая заметка: "boot 1"
I (xxx) nvs: загрузка 2 записана. Заметка теперь "boot 2"
```

## Частые ошибки

- После каждой перезагрузки снова «ключ ещё не создан». Забыли `nvs_commit`, либо прошивка каждый старт вызывает `nvs_flash_erase()`.
- `ESP_ERR_NVS_KEY_TOO_LONG` или ошибка на `nvs_open`. Имя длиннее 15 символов.
- `ESP_ERR_NVS_NOT_ENOUGH_SPACE`. Раздел забит старыми ключами. Для учёбы проще `erase-flash`, в программе — стереть ненужный ключ `nvs_erase_key`.
