# 22. Автоматический лёгкий сон

Программа только печатает номер и вызывает `vTaskDelay` на 3 секунды. Явного `esp_light_sleep_start()` в ней нет. Сон включает связка из трёх вещей:

1. `CONFIG_PM_ENABLE` — в прошивке есть управление питанием;
2. `CONFIG_FREERTOS_USE_TICKLESS_IDLE` — когда все задачи спят, системный тик можно остановить;
3. `esp_pm_configure()` с `light_sleep_enable = true` — остановленный тик разрешено проводить в лёгком сне.

Пока `vTaskDelay` не кончился и других готовых задач нет, чип засыпает. Когда пора снова печатать строку, он просыпается. Переменная `awake` сохраняется: это тот же лёгкий сон, что в [примере 18](../18_light_sleep/README.md), только решение «пора спать» принимает планировщик, а не ваша строка кода.

Ручной вызов из примера 18 нужен, когда сон — часть сценария: «подожди кнопку или 8 секунд и сразу реши, кто разбудил». Автоматический режим нужен в обычной программе, которая и так проводит почти всё время в ожидании очереди, таймера или `vTaskDelay`.

## Частоты

`max_freq_mhz = 160` — потолок ESP32-C3, когда есть что считать. `min_freq_mhz = 40` — нижняя ступень. Пока задачи заняты несильно, частота может опуститься и без полного сна. Это DFS, динамическая смена частоты. `light_sleep_enable` добавляет ещё и остановку процессора.

Обе цифры должны быть из набора, который чип реально умеет. Для C3 пара 160/40 стандартная. Произвольное «min = 10» конфигуратор отклонит.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/22_pm_auto_light_sleep
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Ключи питания лежат в `sdkconfig.defaults`. Если скопировать только `main.c` в проект, где `CONFIG_PM_ENABLE` выключен, `esp_pm_configure` не соберётся: объявление функции закрыто этим ключом.

## Что вы должны увидеть

```text
I (xxx) pm: автоматический лёгкий сон включён
I (xxx) pm: бодрствование 1
I (xxx) pm: бодрствование 2
```

Интервал между строками около трёх секунд. В мониторе сон не выглядит «отключением»: USB иногда придерживает вывод и отдаёт строки пачкой. Что чип действительно спал, видно по току в цепи 3.3 В. В разрыве USB ток почти ничего не скажет: там ещё преобразователь платы и, на части плат, всегда включённый мост USB-UART.

Короткий `vTaskDelay` на 1 мс автоматический сон не включает. Вход в сон и выход из него сами занимают время, и планировщик оставляет такой интервал обычным ожиданием.

## Как это стыкуется с Wi-Fi

Этот пример радио не включает, чтобы было видно чистый сон процессора. В программе с Wi-Fi добавляют модемный сон (`esp_wifi_set_ps(WIFI_PS_MIN_MODEM)` из [примера 12](../12_wifi_station/README.md)). Радио тогда само просыпается на маяки точки доступа, а процессор спит в промежутках. Глубокий сон с сохранённым Wi-Fi так не работает: глубокий сон радио выключает полностью, и связь надо устанавливать заново после каждой загрузки.
