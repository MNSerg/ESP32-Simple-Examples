# 24. Запись и чтение I2C с разбором ошибок

Сканер из примера 10 только спрашивает «есть ли кто по адресу». Здесь мастер уже передаёт байты и принимает их обратно, а каждый код ошибки обрабатывается по-своему.

На ESP32-C3 контроллер I2C один. Мастер и ведомый на одном чипе сразу не запустить, поэтому вторая сторона — настоящая микросхема на шине, а не второй порт того же ESP.

Выводы совпадают с дисплеем исходного проекта:

| Сигнал | GPIO |
| --- | --- |
| SDA | 5 |
| SCL | 6 |

Скорость 100 кГц, внутренние подтяжки включены. На модуле OLED внешние резисторы обычно уже стоят.

## Кто сидит на шине

| Адрес | Роль |
| --- | --- |
| `0x01` | Пустой специально. На нём каждый цикл видна ошибка, даже если ничего не подключено |
| `0x3C` | OLED SSD1306, если он есть. В него уходит команда «включить экран», затем читается байт состояния |
| `0x50` | EEPROM 24Cxx с однобайтным адресом ячейки. Пишется один раз, дальше только чтение |

Команда OLED — байты `0x00`, `0xAF`. Её безопасно повторять. Чужую микросхему с адресом `0x3C` на время примера лучше снять: для неё эти байты могут быть не командой дисплея.

Ячейка EEPROM `0x10` получает значение `0xA5` один раз за запуск. Постоянная перезапись в цикле изнашивает память, у 24Cxx ресурс конечный. После записи микросхема несколько миллисекунд не подтверждает адрес. `probe` в это время возвращает `ESP_ERR_NOT_FOUND`. Здесь это не «устройства нет», а «идёт цикл записи», и программа ждёт, пока ACK не вернётся.

## Три операции

1. `i2c_master_transmit` — только запись.
2. `i2c_master_receive` — только чтение.
3. `i2c_master_transmit_receive` — запись и сразу чтение с повторным стартом. Так читается ячейка EEPROM: сначала адрес ячейки, потом байт данных, шина между ними не отпускается. Две отдельные транзакции этот адрес не сохраняют.

Регистрация `i2c_master_bus_add_device` устройство не опрашивает. Ошибка «никого нет» появляется позже, на обмене.

## Как разбираются ошибки

| Код | Откуда | Что делает пример |
| --- | --- | --- |
| `ESP_OK` | любая операция | обмен засчитан |
| `ESP_ERR_NOT_FOUND` | только `i2c_master_probe` | NACK на пустом адресе или EEPROM занята записью |
| `ESP_ERR_INVALID_RESPONSE` | запись и чтение | тот же NACK, но у другой функции. У живого устройства пробуем ещё до трёх раз |
| `ESP_ERR_TIMEOUT` | шина не закончила обмен | один раз `i2c_master_bus_reset`, повтор без сброса только затягивает зависание |
| `ESP_ERR_INVALID_ARG` | неверный вызов | сразу наружу, повторять незачем |

Пустой адрес `0x01` специально не повторяется: там NACK ожидаем, и три попытки только засорили бы лог.

Несовпадение прочитанного байта EEPROM с записанным — отдельное сообщение. Шина при этом исправна, ошибка уже в данных.

Часть модулей SSD1306 не отвечает на чтение, хотя команды принимает. Пример это пишет предупреждением и идёт дальше.

## Сборка

```bash
. $HOME/esp/esp-idf/export.sh
cd examples/24_i2c_transfer
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

OLED из `project-name` можно оставить. Одновременно с той прошивкой этот пример не запускают: мастер на шине должен быть один.

## Что вы должны увидеть

Без единой микросхемы раз в две секунды:

```text
I (xxx) i2c: пустой адрес 0x01, probe: probe получил NACK, адрес молчит
I (xxx) i2c: запись в 0x01 без повторов: NACK во время записи или чтения
I (xxx) i2c: чтение из 0x01: NACK во время записи или чтения
I (xxx) i2c: OLED 0x3C нет, запись и чтение дисплея пропущены
I (xxx) i2c: EEPROM 0x50 нет, проверка ячейки пропущена
```

С дисплеем вместо строки «OLED нет» будет «в OLED записано включение экрана» и либо байт статуса, либо предупреждение, что модуль статус не отдал. С EEPROM после первой записи появится «EEPROM вернула 0xA5, запись и чтение совпали».

## Частые ошибки

- Таймаут на всех адресах сразу. Нет подтяжки SDA/SCL к 3.3 В, провода перепутаны или линия зажата в ноль.
- `probe` говорит NOT_FOUND, а `transmit` на том же адресе — INVALID_RESPONSE. Это не две разные неисправности: функции называют один и тот же NACK разными кодами.
- EEPROM читается как `0xFF` или другое значение. Цикл записи ещё не кончился, ячейка другого размера адреса (нужны два байта, а не один) или на `0x50` сидит не 24Cxx.
- Дисплей в `project-name` после этого примера погас. Команда `0xAF` его как раз включает. Если картинка пропала, плату просто нужно снова прошить проектом дисплея: этот пример буфер u8g2 не рисует.
